# Advanced usage guide (docs.avalai.ir/fa/guides/advanced-usage — slug inferred; page has front-matter `hasH1: true`)

Advanced techniques for specific API features. Samples use Chat Completions; each has a Responses equivalent block (swaps in generic prompts — informational).

## Chat completions
- Keep relevant history for context but watch token limits; long histories cost more and can make the model lose earlier context → summarize/truncate when needed.
- Use `tools` (function calling) for structured data extraction or acting on external systems: Chat shape `{"type":"function","function":{name,description,parameters}}`; `tool_choice:"auto"` (or force a specific function — not for Claude 5.x / thinking-mode models); read `response.choices[0].message.tool_calls`. Responses shape is FLAT (`{"type":"function","name":…,"parameters":…,"additionalProperties":false}`) and results come as `function_call` items (see function-calling.md; add `strict:true` + `additionalProperties:false` for reliability — the page's samples omit them).

## Embeddings
Normalize vectors to unit length for similarity (cosine = dot product of normalized vectors); t-SNE/UMAP for 2D/3D visualization; chunk long documents (paragraphs/sections) before embedding. Page sample bugs: `normalize` has a broken `return v` indentation (SyntaxError) and the "example usage" is nested inside `cosine_similarity` after `return` (dead code) — rewrite: `v/np.linalg.norm(v)` with a zero-norm guard; `np.dot(a_norm,b_norm)`.

## Image generation (prompting)
Be detailed and specific (objects, setting, style, mood, composition); name style/medium ("photorealistic", "impressionist painting", "cyberpunk art", "watercolor", "digital painting", "photo"); iterate on prompts; "negative prompts" only where the model supports them (not on gpt-image models; see provider-specific-params.md). Good: "detailed digital painting of a bioluminescent forest at night, giant glowing mushrooms, glowing streams, mystical creatures in shadows, fantasy concept art style"; weak: "a magical forest". (Image models: default `gpt-image-2.5-flare`/`-sunburst` — see image-generation.md.)

## Reproducible outputs
Chat completions are non-deterministic by default; improve consistency with `seed` + monitoring `system_fingerprint`: set `seed` to the same integer and keep ALL other params (prompt, `temperature`, …) identical; determinism is best-effort — if `system_fingerprint` differs between responses, system-level changes may alter output. Caveat: `seed`/`system_fingerprint` support is provider/model dependent (reasoning models and non-OpenAI routes may ignore them); `temperature` is rejected by reasoning models/Claude 5.x.

## Managing tokens
Models read/write text in tokens (English ≈ 4 chars ≈ 0.75 word; other languages differ, Persian typically uses more tokens per word). Total tokens affect cost (per token), latency (more tokens = longer) and whether the call works at all (total must fit the context window). Input + output both count (10 in + 20 out = 30 billed). Read `usage` (`prompt_tokens`, `completion_tokens`, `total_tokens`; Responses: `input_tokens`, `output_tokens`). Near the context limit responses may be cut (little room for output). Counting endpoint isn't available (token-counting.md).

## Parameter details
- **Frequency penalty**: reduces repetition of specific tokens in proportion to how often they already appeared. **Presence penalty**: reduces repeating any token that has appeared at all. Reasonable 0.1–1 for mild reduction; up to 2 suppresses strongly but can hurt quality noticeably; negative values increase repetition. Sample: `frequency_penalty=0.7, presence_penalty=0.5`. Not supported by reasoning models; not with `prediction`. Responses has no such params.
- **Logprobs** (`logprobs=True`, `top_logprobs=4`): token logprob = log p(token_t | context, previous tokens); exp(logprob) = conditional probability of that token — NOT the probability the answer/class is correct (a high-prob token can still be wrong). For classification: use short labels expected to be one token (`A`–`D`), `temperature=0`, validate format (exactly one token, label in allowed set, token equals label) else route to human review; accept only if `exp(logprob) ≥ threshold`. `EXAMPLE_THRESHOLD=0.85` is only an example → tune thresholds on a labelled hold-out set against precision/recall goals, cost of a wrong accept and human-review volume; recalibrate after changing model, prompt, label set, language or data distribution. Sequence scoring: sum token logprobs then exp for joint probability (biases toward short outputs); average logprob / perplexity `exp(-avg_logprob)` reduces length effect but only for relative comparison in a controlled setup with the same model+prompt; neither measures correctness. Source: archived OpenAI Cookbook "Using logprobs" (checked 1405-06-17 / 2026-09-08) → pattern reference only; verify `logprobs` support per AvalAI model (not on GPT-5 reasoning models/many non-OpenAI routes; not with `prediction`).
