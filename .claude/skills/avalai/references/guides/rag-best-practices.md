# RAG best practices (docs.avalai.ir/fa/guides/rag-best-practices)

Adapted from "Best Practices for RAG Pipeline" (masteringllm, Medium) for AvalAI. RAG augments an LLM with external knowledge: better accuracy/fresh domain data, fewer hallucinations, updatable knowledge without retraining, source citations. **Build retrieval app-side**: hosted vector stores / `file_search` aren't available on AvalAI (tools-file-search.md, retrieval.md). Related captured: embeddings.md, api-reference/rerank.md, citation-formatting.md, evals.md, optimizing-llm-accuracy.md.

## Pipeline (9 stages)
1 query classification → 2 document chunking → 3 embedding → 4 vector store → 5 retrieval → 6 re-ranking → 7 repacking → 8 summarization (compress to context window) → 9 generation.

## 1. Query classification
Not every query needs retrieval. Use a classifier (small LLM: system "Respond with 'RETRIEVE' if the query requires external knowledge, or 'SUFFICIENT' if the model's knowledge is enough"; match on `"RETRIEVE" in output`; on classifier error default to retrieving) to skip retrieval for questions the model can answer, and consider task type. Sample bug: the example query ("AvalAI's 2025 developer conference") shows retrieval-need detection; Go samples use `openai.ChatCompletionRequest` + lowercase `model:` (compile errors) and a `client.BaseURL` field (not in the official Go SDK) → use raw HTTP or the OpenAI SDK's `option.WithBaseURL`.

## 2. Chunking
Strategies: token-level (fixed tokens), sentence-level (boundaries), semantic (LLM finds natural break points). Practice: **512–1024 tokens**; **10–20% overlap**; keep semantically related content together; enrich chunks with titles/headings/metadata. Sample (`chunk_document_by_sentences` with NLTK `sent_tokenize`, `overlap` = number of sentences, size = word count not tokens) — word counts only approximate tokens (Persian differs); `nltk.download("punkt")` (newer NLTK needs `punkt_tab`); `sent_tokenize` and the PHP regex `(?<=[.!?])\s+(?=[A-Z])` are English-oriented → for Persian split on `؟ . !` + Persian-aware rules (or use a proper tokenizer such as hazm).

## 3. Embeddings
Use retrieval-optimised embedding models; same model for docs and queries; trade dimension (smaller = faster/less accurate); domain-specific models for specialist content. Example uses `text-embedding-3-large`. ⚠ **Dimension error in the page's samples: `dimension = 1536` "for text-embedding-3-large" is wrong — default is 3072** (1536 = `text-embedding-3-small`, or large with `dimensions=1536`); a mismatched FAISS/Milvus dimension raises errors. Batch many chunks in one `input` array (the single-text loop in the samples is slow/costly in requests). Cosine similarity of v3 embeddings = dot product (normalized).

## 4. Vector store
Choose a DB balancing speed/scale/features; tune index (HNSW, IVF); store metadata for filtered retrieval; batch ops. Samples: FAISS `IndexFlatL2` wrapper (`add_texts`, `similarity_search`, `save/load`), Milvus (docker `milvusdb/milvus`, HNSW M=8 efConstruction=64, L2) in Python and Go. Defects: `faiss.write_index(index, f.fileno())` / `read_index(f.fileno())` is wrong — pass a **file path string** (`faiss.write_index(index, "x.faiss")`); L2 on non-normalized vectors vs cosine — use `IndexFlatIP` on normalized vectors for cosine; unpickling `.pkl` files is unsafe for untrusted data (use JSON); the Milvus "already inserted?" check via `limit=len(documents)` is a toy; JS `faiss-node` snippet and Go listings are truncated in the page.

## 5. Retrieval
Dense (vector similarity), sparse (BM25/TF-IDF keyword), hybrid (both). Practice: ensembles; query expansion/rewrite; metadata filtering (apply permission/tenant filters BEFORE retrieval); contextual retrieval using conversation history. Sample `HybridRetriever(texts, dense_weight=0.6)`: dense via embeddings + cosine, sparse via `rank_bm25` `BM25Okapi`, normalize each by max score, combined = w·dense + (1−w)·sparse, returns top-k with contributions. Notes: max-normalisation is crude (use min-max / RRF reciprocal-rank-fusion); BM25 tokenizers are English (`word_tokenize`); JS sample uses `natural.BM25`/`tfidfs` APIs that don't exist as written; Go sample uses `james-bowman/nlp` TF-IDF and is truncated.

## 6. Re-ranking
Improve relevance by re-ordering first-stage results: cross-encoders, two-stage retrieval (retrieve more, then rerank), feature enrichment (recency/popularity), diversification. Python sample uses `sentence_transformers.CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")` — **English-only (MS MARCO), not multilingual** as the comment claims. **On AvalAI use the hosted rerank API** (`POST /v1/rerank`, see api-reference/rerank.md; sample cURL/JS use model `rerank-multilingual-v2.0` — verify exact id in `/v1/models`/rerank.md). The JS sample's `client.reranking.create(...)` does NOT exist in the OpenAI SDK → call the REST endpoint directly (fetch/axios/requests) with `{model, query, documents, top_n}` and read `results[].index` + `relevance_score`; map back via `index` to keep metadata. Sample cURL has an escaped apostrophe bug in the JSON (`it\\'s`).

## 7. Generation
Format retrieved context clearly; include source info for citations; prompt the model how to use context; stream long answers; evaluate regularly. System prompt (Persian in page): answer only from context; if absent say "اطلاعات کافی برای پاسخ به این سوال ندارم"; cite [1],[2]; be concise; clear formatting. Context block: `text` + `[i] منبع: <source>، صفحه: <page>`. No-doc fallback: plain answer without context (decide deliberately — for grounded apps prefer "not enough information"). Prefer stable source IDs + validated citations (citation-formatting.md), place untrusted retrieved text in tagged blocks (prompt-engineering.md). Page's "Responses equivalent" blocks swap in unrelated weather/file examples — ignore.

## 8. Full pipeline (`RAGPipeline` class)
Flow: `add_documents` (embed → FAISS index + texts + metadata) → `query` (classify → `_retrieve` k nearest → `_generate_response` with `[i]` citations) → `save`/`load` (FAISS + pickle). Defects: missing `import os`; `faiss.write_index(..., f.fileno())` (see §4); L2 distances reported as "similarity"; `max_tokens=10` for classifier on reasoning models (use `max_completion_tokens`/`max_output_tokens`, and reasoning models may return empty); classification on the generation model is slow/costly (use a small model); embedding one-by-one; pickle security. For a production design combine: query classifier/rewriter → hybrid retrieve with filters → rerank (`/v1/rerank`) → repack top chunks with source IDs → generate on `/v1/responses` with strict citation rules → eval on labelled questions (evals.md).

## Conclusion
RAG isn't one-size-fits-all: experiment with chunking/embedding/retrieval/reranking configs; continuous evaluation and refinement keep performance up.
