# Audio API (docs: /fa/api-reference/audio)

OpenAI-SDK compatible: `base_url=https://api.avalai.ir/v1`, key `AVALAI_API_KEY`. Related guides: fa/guides/{audio-processing,realtime-audio,speech-to-text,text-to-speech,responses-vs-chat-completions}.

## Choosing a path
| goal | route | when |
|---|---|---|
| text → speech | `POST /v1/audio/speech` | final text ready, want audio file/stream |
| transcribe / translate file | `POST /v1/audio/transcriptions`, `POST /v1/audio/translations` | bounded file/upload |
| direct audio in/out in chat | `POST /v1/chat/completions` with audio model | need `input_audio`, `modalities`, `message.audio` |
| Responses-first voice flow | transcriptions → `/v1/responses` → `/v1/audio/speech` | reasoning/tools/structured output/state |
| live low-latency conversation | Realtime architecture ref (fa/guides/realtime-audio) | only if a live route is enabled for your account; otherwise use request-based endpoints |

## TTS — `POST https://api.avalai.ir/v1/audio/speech`
| param | type | req | notes |
|---|---|---|---|
| `model` | string | yes | `gemini-3.8-flash-tts`, `gemini-3.8-flash-lite-tts`, `gemini-3.1-flash-tts-preview`, `gpt-4o-mini-tts`, `tts-1`, `tts-1-hd`, `gemini-2.5-pro-tts`, `gemini-2.5-flash-tts`, `gemini-2.5-pro-preview-tts`, `gemini-2.5-flash-preview-tts`, `eleven_v3`, `eleven_multilingual_v2`, `eleven_turbo_v2`, `eleven_turbo_v2_5`, `eleven_flash_v2`, `eleven_flash_v2_5`, `groq.playai-tts`, `groq.playai-tts-arabic` (verify live status) |
| `input` | string | yes | OpenAI-compatible ≤4096 chars/request; provider routes differ → split long text by paragraph/scene and concatenate audio |
| `voice` | string \| object | yes | OpenAI: `alloy ash ballad coral echo fable nova onyx sage shimmer verse marin cedar` (try `marin`/`cedar` first for quality; tts-1/tts-1-hd have a smaller set). Gemini 3.8: object `{"name":"Zephyr","languageCode":"en-US"}` = preset voice, NOT voice cloning |
| `instructions` | string | no | style/tone, e.g. `gpt-4o-mini-tts`; not for `tts-1`/`tts-1-hd` |
| `response_format` | string | no | default `mp3`; `mp3 opus aac flac wav pcm`; wav/pcm for lower-latency playback; default/allowed depend on model → send `mp3` explicitly when saving .mp3; `gemini-3.1-flash-tts-preview` requires `pcm` |
| `speed` | number | no | 0.25–4.0 (default 1.0) if supported |
| `stream_format` | string | no | `audio` or `sse` (`sse` not for tts-1/tts-1-hd) |

```bash
curl https://api.avalai.ir/v1/audio/speech -H "Authorization: Bearer $AVALAI_API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini-tts","voice":"coral","input":"امروز روز خوبی برای ساختن چیزی است که مردم دوستش داشته باشند.","instructions":"با لحنی گرم و مطمئن صحبت کن."}' --output avalai_speech.mp3
```
```python
with client.audio.speech.with_streaming_response.create(model="gpt-4o-mini-tts", voice="coral", input="…", instructions="…") as r:
    r.stream_to_file(Path("avalai_speech.mp3"))
```
```javascript
const audio = await client.audio.speech.create({ model:"gpt-4o-mini-tts", voice:"coral", input:"…", instructions:"…" });
await fs.writeFile("avalai_speech.mp3", Buffer.from(await audio.arrayBuffer()));
```

### Gemini 3.8 TTS
- `gemini-3.8-flash-tts` = creative quality, emotional delivery, regional accents, long-dialogue stability; `gemini-3.8-flash-lite-tts` = high throughput/low latency everyday reading. **Text in → audio out only** (no transcription, audio-input chat, Live API, reasoning).
- Available **only** via native `/v1beta/models`, `/v1/chat/completions`, `/v1/audio/speech`. Do NOT send to `/v1/responses`, `/v1/messages`, or legacy `/v1/text:synthesize`. Write the reply with a chat/reasoning model first, then pass final text to TTS.
```bash
curl --fail-with-body -sS https://api.avalai.ir/v1/audio/speech -H "Authorization: Bearer $AVALAI_API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"gemini-3.8-flash-tts","voice":{"name":"Zephyr","languageCode":"en-US"},"input":"Welcome to AvalAI. This voice was generated by AI.","response_format":"mp3"}' --output speech.mp3
```
Native per-turn speaker/style control: fa/api-reference/v1beta#gemini-38-native-text-to-speech (not yet captured).

### TTS notes
Keep `tts-1`/`tts-1-hd` for legacy; use `gpt-4o-mini-tts` for style control. Voice list depends on model family (on voice error use provider-documented voice). Disclose to end users that audio is AI-generated. Custom voices = account/provider-specific, not a default AvalAI endpoint; keep consent records for any cloning workflow. Chunk long texts and stitch.

## Transcription — `POST https://api.avalai.ir/v1/audio/transcriptions` (multipart)
| param | notes |
|---|---|
| `file` (req) | ≤~25 MB for OpenAI-compatible; `flac mp3 mp4 mpeg mpga m4a ogg wav webm`; split/compress bigger |
| `model` (req) | `whisper-1`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize`, `scribe_v1`, `scribe_v2`, `groq.whisper-large-v3`, `groq.whisper-large-v3-turbo` (note: whisper/gpt-4o-transcribe have a provider shutdown 2027-02-26 per deprecations) |
| `language` | ISO-639-1 (`en`, `fa`) — improves accuracy/latency |
| `prompt` | context/spelling/vocab; not all models; not diarize model |
| `response_format` | default `json`. whisper-1: `json text srt verbose_json vtt`; GPT-4o: `json`/`text`; diarize: `diarized_json` |
| `timestamp_granularities[]` | word/segment (esp. whisper-1 + `verbose_json`); word adds latency; not for diarize |
| `stream` | transcript events for non-Whisper models; `whisper-1` can't stream |
| `chunking_strategy` | required for diarization on inputs >30 s; use `"auto"` |
| `include[]` | `logprobs` with `response_format=json` on GPT-4o transcribe models (not whisper-1/diarize) |
| `temperature` | 0–1 |
| `known_speaker_names[]` / `known_speaker_references[]` | diarize routes; ≤4 speakers; refs = 2–10 s clips as data URLs |
```bash
curl https://api.avalai.ir/v1/audio/transcriptions -H "Authorization: Bearer $AVALAI_API_KEY" -F file="@meeting.mp3" -F model="gpt-4o-transcribe" -F response_format="text"
```
```python
with open("meeting.mp3","rb") as f:
    t = client.audio.transcriptions.create(model="gpt-4o-transcribe", file=f, response_format="text",
        prompt="نام محصول‌ها شامل AvalAI، Qwen، Grok، Claude و Gemini است.")
```
JS: `file: fs.createReadStream("meeting.mp3")`.
(`-H "Content-Type: multipart/form-data"` in the source curl is unnecessary — curl sets the boundary itself with `-F`; don't set it manually.)

### Diarization
`gpt-4o-transcribe-diarize`, `response_format=diarized_json`, `chunking_strategy="auto"` (>30 s). Only via `/v1/audio/transcriptions` (not Realtime).
```python
t = client.audio.transcriptions.create(model="gpt-4o-transcribe-diarize", file=f, response_format="diarized_json", chunking_strategy="auto")
for s in t.segments: print(s.speaker, s.start, s.end, s.text)
```
### Streaming events (`stream=true`, GPT-4o transcribe models)
`transcript.text.delta` (partial; with diarization may carry `segment_id`, speaker label finalised later) · `transcript.text.done` (final text + usage) · `transcript.text.segment` (final diarized segment: `speaker,start,end,text`). Use `include[]=logprobs` + `json` for QA/review queues. Don't stream `whisper-1` → use file chunks or a live Realtime route.

## Translation — `POST https://api.avalai.ir/v1/audio/translations`
Audio → **English** text. Model `whisper-1` unless AvalAI enabled another for your account. Params: `file` (req, ≤~25 MB), `model` (req), `prompt` (match audio language), `response_format` (`json text srt verbose_json vtt`), `temperature`.
```python
t = client.audio.translations.create(model="whisper-1", file=open("german.mp3","rb")); print(t.text)
```

## Audio in Chat Completions
Models `gpt-audio-1.5`, `gpt-audio`, `gpt-audio-mini` (⚠ `gpt-audio*` provider shutdown 2027-01-20) support direct audio in/out.
```python
c = client.chat.completions.create(model="gpt-audio-mini", modalities=["text","audio"],
    audio={"voice":"alloy","format":"wav"},
    messages=[{"role":"user","content":"سیاست بازپرداخت ما را با لحنی دوستانه توضیح بده."}])
open("reply.wav","wb").write(base64.b64decode(c.choices[0].message.audio.data))
```
Audio returned base64 at `choices[0].message.audio.data`. Terminal one-liner: request `"format":"mp3"`, `| jq -r '.choices[0].message.audio.data' | base64 --decode > reply.mp3` (macOS `base64 -D`, play with `afplay`; Linux `ffplay -nodisp -autoexit`; PowerShell: `ConvertFrom-Json` + `[Convert]::FromBase64String` → `WriteAllBytes`).

## Responses-first voice flow (Responses doesn't take audio directly)
1. `audio.transcriptions` (gpt-4o-transcribe, `text`) → 2. `responses.create(model=…, instructions=…, input=transcript)` → 3. `response.output_text` → 4. `audio.speech` (gpt-4o-mini-tts, coral). Source example model id `gpt-5.6-luna` (verify live id).

## Errors
400 unsupported param for model (remove `instructions`, timestamps, diarization, modalities) · 401 bad key · 413 file too large (compress/split) · 415 unsupported media type · 429 backoff + check tier.

## Best practices
- Transcription: `gpt-4o-transcribe`/`-mini-transcribe` for quality; `whisper-1` for compatibility/timestamps/translation; diarize only when speaker labels needed; `include[]=logprobs` for confidence.
- TTS: `gpt-4o-mini-tts` for control; tts-1/-hd for legacy.
- Direct voice↔voice via Chat Completions; reasoning/tools/structured output/state via Responses then TTS.
- Log model id, latency, upload size, response format. Meeting intelligence w/ evidence: fa/examples/speaker_aware_meeting_intelligence.
